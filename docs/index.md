# PPT创造大师

PPT创造大师是一款面向中文用户优先设计的智能演示创作平台，目标是让用户通过输入想法生成结构清晰、设计专业的 PPT。

## 首版骨架

当前版本已经落地一个 Next.js 应用骨架。登录后的根路径会按角色分流：普通用户进入“创作工作台”，管理员进入“管理端”。创作工作台采用三步页面流程：先输入原始文本或创作想法，上传资料文件，并选择 PPT 类型和可选页数；资料文件会先通过 `POST /api/decks/outline/files` 在服务端解析和切块，返回 `parsedFiles`、`sources` 和 `warnings`，不落库、不生成 PPT；支持文本、Markdown、CSV、JSON、`.docx`、`.pptx`、`.xlsx`、PDF 和图片文件，旧版 `.doc`、`.ppt`、`.xls` 返回明确不支持提示。页数全链路范围为 6-40，默认 6。点击生成大纲草稿后先生成隐藏输入分析、推荐页数和 L0-L3 轻量大纲，确认页主要展示并允许调整页数、PPT 类型、叙事风格、全局主题、章节结构和页面清单，受众、目标、核心信息继续作为隐藏上下文保存。大纲确认页默认以卡片化只读视图展示整体目录、统一视觉说明、每页详细大纲和可展示内容 JSON，需要调整时点击“编辑大纲”进入完整编辑模式；最后基于已保存的大纲生成语义化页面设计方案、Mock 图片图层、Web 动效、内容审核、一致性评分和 PPTX 下载文件。

应用已接入邮箱密码账号体系，工作台需要登录访问。登录后可在“体验设置”的“通用”页切换语言或退出登录，在“账号”页查看邮箱、维护名称、上传头像和登录密码。头像超过 1MB 时会在上传前压缩，并保存到 `storage/uploads/avatars` 目录。在“外观”页可切换浅色、深色、跟随系统和全应用配色预设。AI 供应商、LLM 模型、图片模型和向量模型按账号隔离管理，并在进入对应设置页签时按需加载；三类模型统一选择供应商、显示名称、模型 ID、默认温度、启用状态和默认状态。配置加载按接口独立容错，某个配置接口失败时不会清空已成功读取的列表。API Key 只在 AI 供应商中维护，使用服务端 AES-GCM 加密后存入 MySQL，界面只显示是否已配置密钥。

应用已提供管理员权限、管理端首页、独立用户管理页、PPT 模板库管理入口和 PPT--To--Slot 入口。管理端首页四个入口卡片采用图标与模块名称并列展示，并把“进入”操作固定在卡片右上角；桌面端入口区收窄整体宽度并居中显示，同时保持每行两个模块，便于快速扫描。通过 `APP_ADMIN_EMAILS` 指定的邮箱会在注册、登录或读取会话时同步为管理员，管理员可查看用户、切换角色、启用或禁用账号；禁用账号会立即清理该用户所有登录会话。管理员可进入“PPT模板库管理”维护 PPT 模板库，模板按章节页、封面大标题、标题 + 正文/要点、大图背景、左右图文、图表、双栏对比、引用/金句页、时间轴、流程/步骤、关键指标页、四象限/矩阵、结束页等固定分类组织，每个模板保存完整页面 JSON 并支持可视化设计器编辑。模板工作区还提供拆表后的语义元素资源库，`TemplateAsset` 公共主表覆盖图标、图形、线条、文本样式、容器组件和导航组件六类资产的治理与检索字段，六张详情表分别保存各类强类型样式字段。PPT--To--Slot 可上传 `.pptx`，提取每页真实坐标、层级、样式和区域结构，生成独立 Slot `template.json`、解析产物、overlay 标注图和人工确认报告；审核通过后写入独立 `PptSlotTemplate` 库，不直接写入现有 `PptTemplate`。语义资产库按空库从零重建，旧 792 条通用资产包不再恢复；当前只保留 `assets/template-assets/common-fallback-v1/` 小型兜底包，可通过 `pnpm db:seed:template-assets -- --dry-run` 校验，并通过 `pnpm db:seed:template-assets` 写入 18 条基础资产。AI 生成资源默认进入待审核池，正式检索只返回启用且已入库资源，并按当前模板套装优先、通用套装兜底。管理员需要创作 PPT 时，可从管理端点击“创作工作台”进入创作页面。

生成链路由 Next.js API 统一承载，外部接口路径保持兼容并新增文件解析接口。`POST /api/decks/outline/analyze` 负责第一轮轻量大纲生成：服务端先按 `GenerationInput` 校验 `idea`、`parsedFiles`、`sources`、`deckType`、`pageCount`、`palette`、`locale`、允许的内容块枚举和每页最多 12 个内容块限制，再返回隐藏意图上下文（受众、目标、核心信息）、推荐页数和 `lightweightOutline`。轻量大纲只覆盖 L0 全局主题、L1 章节、L2 页面清单、L3 每页叙事角色/核心意图；根字段为 `deckTitle`、`deckType`、`narrativeStyle`、`pageCount`、`globalTheme`、`chapters`、`pages`，每页包含 `pageNumber`、`pageType`、`layoutType`、`title`、`purpose`、`keyMessage`、`sourceIds`、`chapterId`、`narrativeRole`。第一轮禁止输出 `contentBlocks`、正文段落、图表数据、图片关键词、坐标、元素层级或具体视觉样式，并立即校验页数、连续页码、章节覆盖、章节重叠、来源 ID 和叙事顺序。`sourceId` 由服务端稳定生成，格式如 `src_f001_c001`，模型只能引用已有来源。用户确认后，`POST /api/decks/outline` 依次生成统一视觉说明结构化 JSON、每页详细大纲和每页可展示内容 JSON。第二轮只决定整套视觉规范；第三轮只决定每页讲什么，不输出 `contentLayers`；第四轮输出可展示文字、数据、标题、副标题、正文要点、`contentBlocks` 和基于 `contentBlocks` 的 `contentLayers` 索引分层，并与详细大纲合并为现有 `SlideContent`。`contentBlocks` canonical 结构为 `{ type, content, priority, sourceIds }`，类型只允许 `heading`、`text`、`list`、`image`、`table`、`chart`、`quote`、`callout`、`metric`、`comparison`、`timeline`、`steps`、`summary`、`conclusion`、`source`；图片、主视觉和背景图需求也必须进入 `image` 类型内容块。`contentLayers` 只保存 `primary`、`supporting`、`supplementary` 三组 0-based `contentBlocks` 下标，不保存新文本，后续只作为信息层级和密度判断。旧 `{ blockType, text, priority }` 和旧字符串层级可读取兼容并归一化。严格校验前会对同一页已有 `contentBlocks` 做窄口径兼容，自动归一化字段别名、常见非法类型和优先级、过滤不存在的 `sourceIds`、移除近重复展示块并按优先级保留最多 12 条，例如课程名、课件名、页脚备注与标题或正文重复时只保留一条。服务端随后执行严格校验，覆盖页数、`deckType`、`locale`、`slideId/index`、轻量大纲/详细大纲/展示 JSON 一致性，以及统一视觉说明不得被后续阶段改写；失败直接返回错误且不保存 `DeckOutlineDraft`，不自动修复、不保存部分草稿。

第 1-5 步结果复用现有字段保存，不新增数据库表：隐藏输入分析、轻量大纲、兼容用 `structureOutline`、`parsedFiles`、`sources` 和文件摘要写入现有 JSON 字段，统一视觉说明写入 `DeckOutlineDraft.unifiedVisualSpec`，每页详细大纲与可展示内容 JSON 合并后写入 `DeckOutlineDraft.slides`。统一视觉说明不保存 Markdown 全文字段，生成、读取和保存时都会清理重复规则，并保存 `themeName`、`visualStyle`、`designIntent`、`usageConvenience`、分组 `colorPalette`、`colorRoles`、`transparencyRules`、`pageSpec`、`typographyRules`、`imageRules`、`componentRules` 和高级规则。`colorPalette` 按 `primary`、`secondary`、`chart`、`neutral`、`accent` 分组，每个颜色都是 `{ name, hex, usage }` 且 HEX 必须为大写；颜色角色只能引用色板颜色，额外允许 `#000000` 与 `#FFFFFF`，透明度只能通过 `{ baseHex, opacity, usage }` 引用色板基色表达。页面默认 16:9、`1920 x 1080px`、`13.333 x 7.5 inch`、安全边距 `0.5`，并记录 12 栏栅格与 `gridGutterPx=24`；`typographyRules.scale` 覆盖封面标题、封面副标题、页标题、小节标题、正文、注释、图表标签和图标标签，`textLimits` 保存标题行数、bullet 字数、注释长度、图标标签长度等限制；`imageRules` 保存 `imageType`、`aspectRatio`、`forbiddenItems` 和 `imagePromptStyle`，背景图需避开高对比文字区域，图片主体不能压在标题区。`componentRules` 独立覆盖卡片、标签、数字指标、表格、图表、图标与轻量元素规范；旧 `string[] colorPalette`、旧 `spacingRules` 和旧数组 `layoutRules` 会在读取时归一化，不需要数据库迁移。

`POST /api/decks/generate` 只接收 `outlineDraftId` 并创建或复用异步预览 PPT 生成任务。用户点击“生成预览PPT”后才执行第六步：同一默认 LLM 模型基于已保存的可展示内容 JSON、每页详细大纲和统一视觉说明输出 `SemanticSlidePlan`，分析页面意图、页面类型、页面任务、内容层级、无坐标语义元素、优先级、视觉角色和布局约束；语义阶段禁止输出坐标、渲染样式和图片请求，并要求 `semanticElements` 覆盖本页全部 `contentBlocks`。覆盖内容块的语义元素必须写入 `contentBlockIndex`，并尽量写入 `styleRole` 以绑定统一视觉规范角色。后续仍由服务端模板选择和确定性排版层生成坐标元素、图片请求、预览占位图、真实图片素材和 PPTX；模板文字位不足时，服务端会把未绑定的 `contentBlocks` 补齐为紧凑文本元素，确保每个可展示内容块都能通过 `contentBlockIndex` 与画布和右侧“本页内容”一一绑定。结果复用 `DeckSlide.pageDesign` 保存，最终元素上限为 24，`motionPlan.elements` 与页面元素使用同一上限，足以容纳 12 个内容块和必要视觉/装饰元素。后台以固定 3 路并发生成页面；前 `min(5, 总页数)` 页会优先按页序写入默认占位图并开放轻量预览，剩余页面、真实图片生成、质量审核和最终 PPTX 合成继续在后台运行；最终合成前会重新按页序读取页面，确保 PPTX 页序稳定。`GET /api/decks/{id}/status` 提供 `previewReady` 与生成进度，只有明确失败才显示失败，长时间任务会继续后台轮询；`GET /api/decks` 只返回已完成且具备 PPTX 产物的历史列表，`GET /api/decks/{id}` 提供账号隔离的详情，生成中的轻量预览可读取但下载和编辑在完成前禁用；PPTX 与图层文件通过鉴权 API 读取。工作台侧栏、大纲详情页和预览详情页支持删除当前账号的大纲草稿或生成历史；删除生成历史会同步清理本地 PPTX 与图片图层产物，生成中的草稿或历史会阻止删除。旧预览不会在读取时自动迁移，缺失落版的历史页面可通过“重新生成当前页”获得完整元素；读取历史数据时若动效计划无效或引用不存在的页面元素，会按当前页面元素自动重建 Web 动效元数据。

## 设计约定

- 默认语言为 `zh-CN`，可在登录后的“体验设置 > 通用”中切换 `en-US`。
- 用户可见文案统一维护在 `messages/`。
- 默认配色预设为“星图”，并提供矩阵、深空、晨雾、月白、竹青、黛蓝、胭脂、鎏金、玄墨；入口位于“体验设置 > 外观”，作用于工作台外壳、按钮和选中态。配色预设同时作为 PPT 生成链路的 `palette` 输入并提供本地 fallback 色板；生成统一视觉说明时最终 HEX 严格锁定到用户选择的预设，AI 只负责名称、用途和角色说明。PPT 页面缩略图、主画布和 PPTX 导出优先使用当前 PPT 统一视觉说明中的 `colorPalette/colorRoles`，模板或语义资产中的固定颜色会在应用到页面时重映射到当前统一色板，不跟随全应用外观预设改色，也不会改写资产库原始颜色。
- 创作输入页的生成意图由创作内容、`PPT 类型`、资料文件和可选页数共同驱动，默认 PPT 类型为“商务汇报”；PPT 类型决定场景结构、视觉基调和页面组织方式。可选指定页数位于上传文件行右侧，范围 6-40，说明文字放在输入框下方；上传文件按钮只显示图标和“添加文件”，单文件大小限制显示在按钮后方，支持格式放在按钮下方；PPT 类型在桌面端使用 4 列等宽网格，分组、选项、样式和交互保持现有设计。输入框、类型选项和右侧栏采用更紧凑的桌面尺寸，重置和生成大纲草稿操作位于右侧栏下方并使用整行宽按钮。
- 大纲确认页默认展示只读卡片化大纲，保留封面、目录、章节和内容页的纵向结构；统一视觉说明采用摘要优先展示，常用视觉基调、色彩、字体和图片规则默认展开，图片生成/使用规则、规则清单和高级规则使用与“版式与字体”一致的两列信息卡展示，完整字号层级与高级规则默认折叠以减少占用空间；预览/编辑状态、页数和“编辑大纲”入口位于底部操作栏中间，用户可直接生成预览 PPT，也可点击“编辑大纲”后修改标题、摘要、每页详细大纲、可展示内容 JSON 和结构化统一视觉说明字段。保存或生成会继续复用同一份大纲草稿。
- PPT 预览页右侧栏展示唯一的“本页内容”面板，面板合并 `contentBlocks` 与全部画布图层：已绑定页面元素的内容块显示元素类型图标、图层层级、`contentBlock` 类型、内容和优先级；未绑定内容块保留显示并标记“未落版”；未绑定图片、形状、图标、图表、背景和装饰等图层以“图层”条目追加显示，并可点击选中。点击“本页内容”条目、画布元素或选中元素时会同步高亮；底部元信息区上方保留“选中元素”编辑器，可编辑文字内容、位置和大小，图片、图标等文件类元素继续提供“上传新文件”和“删除”，下方只保留图片图层请求并随选中图片元素高亮。顶部内容审核与一致性评分只常驻显示标题和分数，摘要改为鼠标悬停或键盘聚焦评分卡时通过 shadcn/ui 风格提示框显示；顶部提供“统一视觉说明”按钮并以大弹窗只读展示完整视觉规范，其后提供“设计质量评分”按钮，进入 `/{locale}/workbench/preview/{id}/quality` 独立页面查看每页总分、五维评分、问题、建议、自动修复状态、选中版式与候选版式；新生成或重新生成页面必须让全部 `contentBlocks` 可点击，设计质量评分会在仍有未落版内容块时降低表达完整性并写入问题；点击“编辑正文条目”后只修改 `bodyPoints` 并同步到画布正文/卡片文本元素。
- 右侧栏的大纲草稿和生成历史卡片提供删除图标；大纲详情页底部操作栏和 PPT 预览详情页顶部操作区也提供删除入口，删除前会使用应用内 shadcn/ui 风格弹窗二次确认，不使用浏览器原生确认框。
- PPT 类型在 AI 生成链路中作为场景结构参考值；每轮 LLM 输出都必须与用户原始选择保持一致，不能由模型改写、翻译或替换。历史 JSON 中残留的 deck-level `style` 字段只做读取兼容，归一化后不会暴露给新前端，也不再作为生成控制项。
- 内置 PPT 类型按使用场景分组，包括商务办公、销售市场、教学培训、研究分析和个人展示；销售市场包含运营方案和增长实验。
- 浅色、深色、跟随系统由本地主题 Provider 管理，入口位于“体验设置 > 外观”。
- 当前生成流程优先调用 OpenAI-compatible 文本模型；未配置 `OPENAI_API_KEY` 时使用本地模拟 fallback。
- 若当前账号配置了启用的默认 LLM 模型，AI 拆页优先使用账号配置；否则回退到 `.env` 中的 OpenAI-compatible 配置。
- AI JSON 生成会先使用结构化输出，再退回 JSON mode；若兼容服务商暂不支持 `json_schema` 类型的 `response_format`，会在重试提示中附带 JSON Schema。大纲草稿的统一视觉、详细大纲和可展示内容阶段不做 schema 失败后的模型改写重试，只保留窄口径格式兼容和严格 zod 校验；第四阶段会对已有 `contentBlocks` 的字段别名、旧类型、非法类型、空字段、无效 `sourceIds`、超界 `priority`、重复文本和超过 12 条的低优先级内容做归一化，最终统一从 `block.type`、`block.content`、`block.sourceIds` 读取；预览 PPT 单页语义编排会继续要求 `contentHierarchy.tiers` 三层均非空，兼容模型返回空层级时会在校验前用页面副标题、来源要求或讲解备注补足空 `items`，但不会放宽最终 zod schema。
- LLM、图片和向量模型拉取都会按常见模型品牌前缀过滤当前供应商返回结果，例如豆包只展示 `doubao-*`，避免同一兼容接口混入其他模型品牌。
- `/{locale}` 是角色分流入口，创作工作台路径为 `/{locale}/workbench`，管理端路径为 `/{locale}/admin`。
- 用户管理页路径为 `/{locale}/admin/users`，PPT 模板库管理路径为 `/{locale}/admin/templates`，PPT--To--Slot 路径为 `/{locale}/admin/ppt-to-slot`，模板设计器路径为 `/{locale}/admin/templates/{id}`；模板工作区的语义元素资源路径包括 `/{locale}/admin/templates/icons`、`/{locale}/admin/templates/shapes`、`/{locale}/admin/templates/lines`、`/{locale}/admin/templates/text-styles`、`/{locale}/admin/templates/containers` 和 `/{locale}/admin/templates/navigation`；普通用户访问管理端路由会被重定向回创作工作台。
- 通用模板库 v1 的设计规范位于 `docs/guide/universal-ppt-template-spec.md`，静态 JSON 包位于 `assets/templates/universal-v1/`；该包基于当前 15 个固定模板分类生成 45 套模板，覆盖“中国商务通用”“AI 科技感”“极简咨询风”三种方向，管理员可在模板库顶部一键导入并替换固定分类旧模板。
- 通用语义兜底资产 v1 位于 `assets/template-assets/common-fallback-v1/`，按图标、图形、线条、文本样式、容器组件和导航组件各提供 3 条基础资产；旧 792 条通用语义资产包已清空，不再参与种子和正式检索。
- 图片图层第一版使用可插拔 Mock SVG 生成器，后续可替换为真实图片生成服务；轻量预览阶段先用 Mock SVG 占位图保证前几页快速可看，真实图片素材按账号内缓存复用，单张图片生成或下载超时会自动降级为 Mock SVG，生成后写入 `storage/assets` 和项目资产目录；PPTX 第一版静态导出并写入 Web 动效备注/metadata，Web 预览支持动效播放。
