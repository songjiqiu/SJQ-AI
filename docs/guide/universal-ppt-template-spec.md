# 通用 PPT 模板设计规范

本文档定义“PPT创造大师”通用模板库 v1 的设计方案、静态 JSON 包和管理端批量导入方式。当前模板包可写入现有 `PptTemplate` 模板库，不新增数据库表；导入并启用后，可被创作生成流程的服务端模板选择链路读取和套用。

## 设计目标

通用模板库沿用管理端现有 15 个固定分类，每个分类规划 3 套通用变体，共 45 套：

- 中国商务通用：浅底、蓝绿强调，适合汇报、方案、培训和运营复盘。
- AI 科技感：深浅均可，使用青色、绿色、琥珀色等科技信号色，避免整套只依赖紫蓝渐变。
- 极简咨询风：白底、黑灰文字、单一高亮色，强调强栅格、高信息密度和结论先行。

市面优秀 PPT 模板库通常以成套主题和可复用页型组织内容，例如封面、章节、内容要点、图文、数据图表、对比、时间轴、流程、引用和结尾页。当前 15 个分类已经覆盖这组主干，因此 v1 不新增分类。

## JSON 包

通用模板 JSON 包位于 `assets/templates/universal-v1/`，包含 45 个模板文件和 `manifest.json`：

- 每个模板文件使用现有 `ppt-template-import-v1` 格式，可通过管理端“PPT模板库管理”的“新建模板 > 导入 JSON”单文件导入。
- `manifest.json` 使用 `ppt-template-manifest-v1`，记录模板分类、风格、中文名称、文件路径和排序，供人工检查或后续批量导入能力复用。
- 文件名使用 ASCII，例如 `assets/templates/universal-v1/chapter/chapter-business-general.json`。
- 管理端模板库顶部提供“导入通用模板”按钮，可一键导入该包。导入前会删除 15 个固定分类下的全部旧模板，再创建 45 个通用模板记录。

## 共通约束

- 画布固定为 16:9，`13.333 x 7.5 inch`，安全边距 `0.5`，按 12 栏栅格组织内容。
- 每页只保留 1 个主标题、1 个核心表达区、最多 1 个主视觉。
- 单页元素数量控制在 `3-10` 个以内，图片请求数量不超过现有 schema 上限。
- 同一固定分类下三套风格模板的 layout signature 必须各不相同。签名只统计元素类型、语义类型、坐标尺寸和图片请求类型，不把文案、名称、ID 当成差异。
- 图片类模板遵守无文字原则：图片不含水印、不含复杂文字、不压标题区。
- 图表页优先保留明确的标题结论、图表主体、来源或口径说明。
- 设计稿不得复制第三方模板资产，只提炼结构、节奏和表达规律。

## 模板方案

| 固定分类 | 中国商务通用 | AI 科技感 | 极简咨询风 |
| --- | --- | --- | --- |
| `chapter` 章节页 | 章节编号分栏：左侧大号 PART 编号，右侧章节标题与两行承接说明，底部细线提示进度。 | 星图坐标章节：深色背景，编号像坐标标签，右侧使用点线网格作弱视觉锚点。 | 大留白分割章：白底、细分割线、左上小编号，中部只放章节标题和一句问题。 |
| `cover-title` 封面大标题 | 年度汇报封面：左侧标题与副标题，右侧抽象业务主视觉，底部放日期/组织占位。 | 智能中枢封面：大标题叠加环形或节点主视觉，突出 AI 平台与生成能力。 | 一句话封面：整页只保留强标题、副标题和小型署名信息，图形极少。 |
| `title-body-points` 标题 + 正文/要点 | 三卡要点：顶部结论标题，下方三张等宽信息卡承载三条行动建议。 | 发光节点要点：要点作为三个节点串联，节点旁放短句，弱化传统卡片边框。 | 结论 + 证据条：左侧结论，右侧纵向三条证据，强调咨询式推理。 |
| `big-image-background` 大图背景 | 半遮罩场景页：全幅场景图，左侧半透明遮罩承载标题与核心句。 | 数据宇宙背景：低对比抽象数据背景，前景使用高对比标题和小标签。 | 黑白大图标题：黑白照片背景，极少色彩，只用一条高亮线标记主题。 |
| `left-image-right-text` 左图右文 | 案例图左文右：左侧案例或场景图，右侧标题、核心句和三条说明。 | 产品视觉左文右：左侧产品/能力插画，右侧说明 AI 能力、效果和适用边界。 | 报告图左文右：左图作为证据，右侧用标题、结论和脚注形成报告页。 |
| `left-text-right-image` 左文右图 | 观点先行右图：左侧先给结论和要点，右侧图片强化场景。 | AI 流程插画右：左侧描述智能流程，右侧透明背景插画承载算法/节点意象。 | 证据图右置：左侧简短结论，右侧证据图，页面底部放来源说明。 |
| `left-text-right-chart` 左文右图表 | 结论 + 柱线图：左侧业务结论，右侧柱线组合图占位。 | 模型指标面板：左侧解释指标含义，右侧仪表盘式图表占位。 | 咨询图表拆分：左侧一句 takeaway，右侧标准图表，底部脚注。 |
| `big-chart` 大图表 | 单图表结论页：顶部一句结论，下方大面积趋势或对比图。 | 数据驾驶舱：深色或浅色面板承载大图表，辅助小指标弱化处理。 | 全宽趋势图：白底全宽图表，标题像报告结论，网格线极轻。 |
| `two-column-compare` 双栏对比 | 现状 / 目标：左右两栏对称，左侧问题，右侧目标与收益。 | 人工 / 智能：左侧传统方式，右侧 AI 方式，中间用箭头或细线转化。 | 方案 A / B：两栏严格同构，每栏按维度列出优劣与适用条件。 |
| `quote` 引用/金句页 | 领导/客户金句：大号引用句居中，来源位于右下，背景保持浅色。 | 核心洞察光标：深色背景，大字金句旁放光标或扫描线式强调形状。 | 黑白大字引用：白底或黑底，超大字重，来源极小，留白充足。 |
| `time-axis` 时间轴 | 里程碑横轴：横向三到五个节点，节点上下错落，适合项目推进。 | 技术演进轨道：节点沿轨道推进，使用发光点标记关键技术阶段。 | 咨询路线图：细线横轴，节点为编号卡片，每个节点只保留短结论。 |
| `process-steps` 流程/步骤 | 三步闭环：三张步骤卡加连接线，适合方法论、操作流程和项目路径。 | 智能生成流水线：输入、分析、生成、导出四段式流程，使用节点和流向线。 | 编号步骤：大编号 + 短标题 + 一行说明，避免复杂图形。 |
| `key-metrics` 关键指标页 | 大数字 + 解释：左侧超大指标，右侧解释指标含义和行动建议。 | 指标仪表盘：关键数字放在仪表盘或环形图中，旁边放辅助指标。 | KPI 结论页：一个 KPI、一句结论、两条解释，版面极简。 |
| `quadrant-matrix` 四象限/矩阵 | 优先级矩阵：横轴价值、纵轴紧急度，四象限承载行动判断。 | 能力/价值象限：横轴智能化程度，纵轴业务价值，突出高潜机会区。 | 咨询 2x2：标准 2x2 矩阵，坐标轴和标签极简，重点象限高亮。 |
| `ending` 结束页 | 行动号召：感谢语、下一步行动和联系方式/二维码占位。 | 下一步智能协作：以“开始生成下一份 PPT”为核心行动，配弱科技视觉。 | 极简谢谢：大号谢谢或结论句，底部小字放联系信息。 |

## 落库映射

JSON 包已经按现有接口与类型生成：

- 分类使用 `pptTemplateCategoryIds`，不新增自定义分类。
- 单页版式使用 `slideLayoutTypeIds` 中的同名值。
- 页面 JSON 使用 `SlideCompositionPlan`，其中 `designPlan.layoutTemplate` 与分类保持一致。
- 模板名称采用“分类名 + 风格名”，例如“封面大标题 - 智能中枢封面”。
- 标签至少包含分类名、风格名和适用场景，例如“封面大标题”“AI 科技感”“AI 路演”。
- 图片类模板使用 `generatedImage` 与 `imageLayerRequests` 占位；`big-image-background` 使用 `imageType: "background"` 且非透明，其余主视觉使用透明插画请求。
- 批量导入接口为 `POST /api/admin/templates/universal-v1/import`，仅管理员可调用。接口读取 `manifest.json`，校验 45 个模板文件与清单一致后，在事务中替换固定分类模板。

## 验收规则

- 规范覆盖 15 个固定分类，每个分类正好 3 套方案，总数为 45 套。
- 每套方案都能转换为现有 `SlideCompositionPlan`，不突破元素数量、图片请求数量、画布坐标、标题唯一性和安全边距约束。
- `tests/universal-ppt-template-json.test.ts` 会校验 45 个模板文件、manifest、schema 兼容性、图片请求引用完整性，以及每个分类内 3 个 layout signature 均不同。
- 管理端批量导入由 `tests/admin-templates-universal-import.test.ts`、`tests/admin-templates-universal-import-route.test.ts` 和管理端组件测试覆盖。
- 至少抽样组合 5 套完整 PPT：商务汇报、销售方案、培训课程、研究报告、路演介绍。
- 视觉验收重点检查标题层级、正文可读性、色彩对比度、留白、图表承载区和缩略图可读性。
- 批量导入按钮、确认弹窗和 toast 文案同步维护 `messages/zh-CN.json` 与 `messages/en-US.json`。
